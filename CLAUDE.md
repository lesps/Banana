# CLAUDE.md

Banana: an offline-first PWA for logging food in bananas (1 banana ≈ 100 kcal), modeled on the iOS app One Banana. No backend; everything lives in `localStorage` on the device, with JSON export/import. `SPEC.md` describes the behaviour and data format and is kept accurate to the code.

## Stack
Vite 8 + vanilla ES modules (no framework), `vite-plugin-pwa` (generateSW, autoUpdate), Vitest 5 + jsdom, sharp (icon script only), `@fontsource/fredoka` (500/600, numbers and headings; body text is the system font).

## Commands
```bash
npm ci
npm test                              # tests/lib + tests/ui (TZ=America/New_York, set in vitest.config.js)
npm run build && npm run test:build   # tests/build runs against dist/
npm run dev | npm run preview
npm run icons                         # regenerate public/ icons from assets/icon.svg; commit the output
npm run foods -- path/to/surveyDownload.json   # regenerate src/data/foods.json from the FNDDS JSON; commit the output
BASE_PATH=/banana/ npm run build      # sub-path build (CI sets /<repo-name>/)
```

## Layout
- `src/lib/` — pure logic, no DOM.
  - `units.js`: amounts are integer **half-bananas** (`halves`). `formatHalves` (3 → `1½`), `clampHalves` (1..`MAX_HALVES` 200), `QUICK_HALVES` [1,2,3,4,6], `bananaRow(total, target, cap=40)` → `{ icons: [{ fill: 0|1|2, over }], more }`, `bananaWord`, `countEntries`.
  - `day.js`: days are local `'YYYY-MM-DD'` strings (they sort chronologically). `dayOf(ts, rolloverHour)` (before the rollover hour counts as the previous day), `addDays`/`daysBetween` (step via local noon, DST-safe), `isDay`, `formatDay` ("Today", "Yesterday", "Fri, Oct 30", year only if different), `shortDay`, `weekdayLetter`, `formatTime`, `hourLabel`. All formatting is `en-US`.
  - `log.js`: entry operations, all returning new arrays. `createEntry`, `addEntry`, `updateEntry` (halves/label/day only; invalid day ignored), `deleteEntry` (sets `deleted: true`), `restoreEntry`; every change sets `updatedAt`. Views over live entries: `live`, `entriesForDay`, `dayTotal`, `daySummaries`, `recentLabels`, `series(entries, endDay, n)`, `recentAverage(entries, today)` (logged days among the 7 before today), `backupDue(entries, lastExport, now)`.
  - `plate.js`: the plate, `[{ halves, label? }]`: `addToPlate` (returns `null` past `MAX_HALVES`), `undoPlate`, `plateTotal`, `plateLabel` (chip labels joined with " + ", no repeats), `formatPlate` ("1 + 2 + ½ = 3½", last 3 amounts), `sanitizePlate`, `platePieces` (what to draw: a whole per 2 halves, a half per odd one, per item).
  - `settings.js`: `DEFAULT_SETTINGS` `{ targetHalves: null, rolloverHour: 4, updatedAt: 0 }`, `sanitizeSettings`, `MAX_ROLLOVER` 11.
  - `foods-build.js` (build-time only, used by `scripts/build-foods.mjs`): `buildFoods(fndds)` → `{ source, foods, skipped }`, `cleanName`, `portionLabel`. The rules are in SPEC "Food data".
  - `foods.js`: `normalize`, `prepareFoods(data, { aliases, pins })` → index, `searchFoods(index, query, { limit })` → `{ results: [{ code, name, portions: [{ label, halves, typical }] }], total }`. Alias-expanded matches first, then literal; ranking in SPEC "Look up".
  - `food-aliases.js`: hand-kept `ALIASES` (whole query or single word → FNDDS words) and `PINS` (query → FNDDS food codes, which must match the query). `tests/lib/foods-data.test.js` checks every pin against the real list.
  - `backup.js`: `exportData`, `backupFilename`, `parseBackup` (validates, skips and counts bad entries, keeps the newest copy of a repeated id), `validEntry`, `mergeBackup` (last writer wins per id on `updatedAt`, ties keep local; settings merge on their own `updatedAt`; returns `report { added, updated, removed, unchanged }`), `summarize`.
- `src/ui/` — DOM.
  - `app.js`: `mountApp(root, { storage, now, saveFile, env, loadFoods })` → `{ actions, state(), destroy() }`. `loadFoods` defaults to a dynamic import of `src/data/foods.json` (its own chunk, precached); it runs the first time Look up opens, and the prepared index lives outside state (`foodIndex`), with `state.lookup = { query, status: idle|loading|ready|error }`. Owns state and persistence, renders the current view plus the tab bar on every change (whole-view re-render; focus and caret restored through `data-focus`). The label being typed (`draft`) lives outside state so typing doesn't re-render; so does `pop` (`{ day, from }`, the day's total just before a log), which the next render passes to the Today view and then clears, so the just-logged bananas animate exactly once; `dropFrom` (index of the first plate item added since the last render) is the same kind of one-shot, for bananas dropping onto the plate. `state.day` is `null` while following today. Storage keys `banana:entries:v1`, `banana:settings:v1`, `banana:lastExport:v1`, `banana:plate:v1` (`KEYS`; the plate is a device-only draft, not in backups). Quick buttons and chips call `actions.addToPlate`; `logPlate` commits one entry through `log(halves, label)` (label: typed draft, else `plateLabel`); Look up portions call `addFromLookup(halves)`, which adds to the plate and returns to Today without touching `state.day`. Listens for `visibilitychange` and checks every minute so "today" follows the rollover.
  - `today.js`, `lookup.js`, `history.js`, `settings.js`: view renderers taking `{ state, today, day, draft, setDraft, pop, actions }` and returning nodes. `today.js` also exports `emptyState(text)` (the swaying smiling banana, shared with History) and `statusText`. `lookup.js` never logs or changes entries; its portions only add bananas to the plate. `banana.js`: the inline SVG sprite (`SPRITE`, symbols `banana`, `banana-half`, `banana-face`), `ensureSprite()` (called by `mountApp`, once per document), `banana(fill, { over, pending, pop, i })` → `span.b.f0|f1|f2` (`.pending`: on the plate, drawn lighter with a wobble) with `<use>`s (`use.ghost` is the empty outline), `bigBanana()`, and `SILHOUETTE` (outline path for the tab icon and page pattern). Icons whose fill grew since `pop.from` get `.pop` and a `--i` stagger index; history bars with no entries get `.zero` (no stem). `plate-art.js`: `plateArt(plate, dropFrom)` draws the plate (SVG ellipses coloured by `--rim`, `--rim-edge`, `--well`, `--plate-shadow`) with sprite bananas at fixed `SLOTS` (14; extra shown as `+N`), drawn back to front; numbers only go into its markup. `swipe.js`: `attachSwipe(row, { onTap, onDelete, onAgain })` (pointer events; axis decided after 8 px; `touch-action: pan-y` keeps vertical scrolling native; the row's `<li>` gets `commit-left|right` past the full-swipe point; one open row at a time, closed by any press outside it) and the pure `swipeOutcome(dx, width)`. Today's entry rows use it: left → `actions.remove`, right → `actions.addToPlate(halves, label)`, tap → editor. `editor.js`: the edit dialog (owns its own draft values until Save). `dom.js`: `h()`, `stepper()`, `openDialog`/`closeDialog` (falls back to the `open` attribute where `showModal` is missing, e.g. jsdom). `toast.js` (one at a time, optional action button), `install.js` (`detectEnv`, iOS install help), `files.js` (`saveFile`: Web Share with files, else download; resolves `false` when the share sheet is cancelled), `storage.js` (`createStorage(backend)`: JSON get/set/remove that never throw; localStorage or memory).
- `src/main.js`: entry point (fonts, CSS, `navigator.storage.persist()`, SW registration). Untested by design; keep logic out of it.
- `src/styles.css`: tokens with light/dark themes. Sprite colours are custom properties (`--peel`, `--shade`, `--shine`, `--ridge`, `--neck`, `--stem`, `--stem-end`, `--flesh`, `--seeds`, `--spot`, transparent unless overripe) that inherit into the `<use>` trees; `.b use.ghost` sets them all to `--ghost`; `.b.over` swaps in `--ripe-*` and `--spot-ink`; `.mini .b` is one colour. `--pattern` is the tiled page background built from `SILHOUETTE` (one tile per theme, fill inlined; regenerate it if the silhouette changes). `.bar.over` fills use `--ripe-peel`/`--spot-ink`. `assets/icon.svg` is the app icon source (the sprite art with colours inlined).
- `src/data/foods.json`: generated, committed; never edit by hand (fix the build rules, aliases or pins instead).
- `tests/lib`, `tests/ui` (jsdom via `// @vitest-environment jsdom`; `tests/ui/helpers.js` mounts with memory storage, a controllable clock, a recording `saveFile` and a small `FOODS` fixture for `loadFoods`), `tests/build` (separate config `vitest.build.config.js`).
- `.github/workflows/deploy.yml`: test, build, build tests, deploy to GitHub Pages on push to `main`.

## Rules
- TDD: write or update the failing test first. Flag any untested change.
- User text goes through `textContent` (the `h()` children). `h(..., { html })` is for static markup only, never data.
- Never derive an entry's day from its timestamp after creation; `day` is stamped once (see SPEC "Entry").
- Never hard-delete entries: deletion is a `deleted: true` marker so merges can't resurrect it.
- The food list is a reference for estimating. Look up may only add bananas to the plate; never log from it or put food-database details (names, codes) into entries.
- Changing the backup format means bumping `VERSION` in `backup.js` and keeping `parseBackup` able to read version 1.
- Keep README, CHANGELOG, SPEC and this file accurate to the code.
