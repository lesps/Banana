# CLAUDE.md

Banana: an offline-first PWA for logging food in bananas (1 banana ≈ 100 kcal), modeled on the iOS app One Banana. No backend; everything lives in `localStorage` on the device, with JSON export/import. `SPEC.md` describes the behaviour and data format and is kept accurate to the code.

## Stack
Vite 8 + vanilla ES modules (no framework), `vite-plugin-pwa` (generateSW, `registerType: 'prompt'`), Vitest 5 + jsdom, sharp (icon script only), `@fontsource/fredoka` (500/600, numbers and headings; body text is the system font).

## Commands
```bash
npm ci
npm test                              # tests/lib + tests/ui (TZ=America/New_York, set in vitest.config.js)
npm run build && npm run test:build   # tests/build runs against dist/
npm run dev | npm run preview
npm run icons                         # regenerate public/ icons from assets/icon.svg and public/splash/ launch screens; commit the output
npm run foods -- path/to/surveyDownload.json   # regenerate src/data/foods.json from the FNDDS JSON; commit the output
BASE_PATH=/banana/ npm run build      # sub-path build (CI sets /<repo-name>/)
```

## Layout
- `src/lib/` — pure logic, no DOM.
  - `units.js`: amounts are integer **half-bananas** (`halves`). `formatHalves` (3 → `1½`), `clampHalves` (1..`MAX_HALVES` 200), `QUICK_HALVES` [1,2,3,4,6], `bananaRow(total, target, cap=40)` → `{ icons: [{ fill: 0|1|2, over }], more }`, `bananaWord`, `countEntries`.
  - `day.js`: days are local `'YYYY-MM-DD'` strings (they sort chronologically). `dayOf(ts, rolloverHour)` (before the rollover hour counts as the previous day), `addDays`/`daysBetween` (step via local noon, DST-safe), `isDay`, `formatDay` ("Today", "Yesterday", "Fri, Oct 30", year only if different), `shortDay`, `weekdayLetter`, `formatTime`, `hourLabel`. All formatting is `en-US`.
  - `log.js`: entry operations, all returning new arrays. `createEntry` (optional `meal: { id, name }`), `addEntry`, `updateEntry` (halves/label/day, and `mealName` for an entry in a meal; invalid day ignored), `deleteEntry` (sets `deleted: true`), `restoreEntry`; every change sets `updatedAt`. `newId`. Views over live entries: `live`, `entriesForDay`, `dayTotal`, `daySummaries` (a meal counts once), `dayRows(entries, day)` (`{ type: 'entry', entry }` or `{ type: 'meal', id, name, day, ts, halves, parts }`, name from the most recently changed part), `mealParts(entries, mealId, day)`, `recentLabels`, `series(entries, endDay, n)`, `recentAverage(entries, today)` (logged days among the 7 before today), `backupDue(entries, lastExport, now)`.
  - `plate.js`: the plate, `{ parts: [{ id, label?, amounts }], active }` (`EMPTY_PLATE`, `MAX_PARTS` 8). `addAmount` (quick buttons → the active part), `addPart` (chips, Again, Look up → a new named part, or fills an empty unnamed active one), `newPart`, `selectPart`, `undoPlate` (last amount of the active part, then the part), `removePart`, `updatePart` (part dialog; a changed amount replaces the taps), each returning `null` past `MAX_HALVES` or `MAX_PARTS`; `plateTotal`, `partHalves`, `partName` ("Part N" when unnamed), `filledParts` (what Log writes), `formatPlate` (a lone part's taps or each part's total, last 3), `sanitizePlate` (also reads the pre-1.10 flat list as one part), `platePieces` (`{ key, kind, part }`: a whole per 2 halves, a half per odd one, per tap; keys stable while the piece stays).
  - `heap.js`: plate geometry in well radii. `wedgeAngles(halvesPerPart)` (proportional from the back, clockwise, `MIN_WEDGE` 0.6 rad by water-filling; a lone part gets the full circle), `bananaSize(count)` (stepped), `pickShown(pieces, max)` (round-robin across parts), `settle(pieces, wedges, size)` → `{ key, x, y, z, rot }` (each piece, in order, tries 48 seeded spots in its wedge and takes the lowest heap height plus `SPREAD` × distance from the wedge's heart; deterministic per key, so earlier pieces never move when later ones land).
  - `settings.js`: `DEFAULT_SETTINGS` `{ targetHalves: null, rolloverHour: 4, updatedAt: 0 }`, `sanitizeSettings`, `MAX_ROLLOVER` 11.
  - `foods-build.js` (build-time only, used by `scripts/build-foods.mjs`): `buildFoods(fndds)` → `{ source, foods, skipped }`, `cleanName`, `portionLabel`. The rules are in SPEC "Food data".
  - `foods.js`: `normalize`, `prepareFoods(data, { aliases, pins })` → index, `searchFoods(index, query, { limit })` → `{ results: [{ code, name, portions: [{ label, halves, typical }] }], total }`. Alias-expanded matches first, then literal; ranking in SPEC "Look up".
  - `food-aliases.js`: hand-kept `ALIASES` (whole query or single word → FNDDS words) and `PINS` (query → FNDDS food codes, which must match the query). `tests/lib/foods-data.test.js` checks every pin against the real list.
  - `changelog.js`: `parseChangelog(text)` → `[{ version, date, intro, items }]` (plain text; `###` subsections skipped), `compareVersions`, `notesSince(releases, seen, current)` (after `seen` up to `current`, newest first; all up to `current` when `seen` is null), `releasesUpTo`.
  - `backup.js`: `VERSION` 2 (added `meal`; reads 1 and 2), `exportData`, `backupFilename`, `parseBackup` (validates, skips and counts bad entries, keeps the newest copy of a repeated id), `validEntry` (drops a malformed `meal`, keeps the entry), `mergeBackup` (last writer wins per id on `updatedAt`, ties keep local; settings merge on their own `updatedAt`; returns `report { added, updated, removed, unchanged }`), `summarize`.
- `src/ui/` — DOM.
  - `app.js`: `mountApp(root, { storage, now, saveFile, env, loadFoods, version, changelog })` → `{ actions, state(), destroy() }`. `loadFoods` defaults to a dynamic import of `src/data/foods.json` (its own chunk, precached); it runs the first time Look up opens, and the prepared index lives outside state (`foodIndex`), with `state.lookup = { query, status: idle|loading|ready|error }`. Owns state and persistence, renders the current view plus the tab bar on every change (whole-view re-render; focus and caret restored through `data-focus`). The label being typed (`draft`) lives outside state so typing doesn't re-render; so does `pop` (`{ day, from }`, the day's total just before a log), which the next render passes to the Today view and then clears, so the just-logged bananas animate exactly once. `plateView` (from `createPlateView`) is made once per mount and passed to the Today view, which calls `plateView.update(plate)` on every render. `state.day` is `null` while following today. Storage keys `banana:entries:v1`, `banana:settings:v1`, `banana:lastExport:v1`, `banana:plate:v1` (`{ parts, active }`; older flat lists are migrated on read), `banana:seenVersion:v1` (`KEYS`; the plate is a device-only draft, not in backups). Quick buttons call `actions.addToPlate(halves)` (active part); chips, Again and Look up call `actions.addPart(halves, label, patch)`; also `newPart`, `selectPart`, `editPart` (part dialog), `undoPlate`, `clearPlate`; a refused change toasts which limit it hit. `logPlate`: one filled part → `log(halves, draft || part label)`; several → one entry per part sharing a new `meal` named with the draft, one Undo for all. `addFromLookup(halves, label)` = `addPart` with `{ view: 'today' }` (doesn't touch `state.day` or the draft). Meals: `editMeal`/`saveMeal` (writes name and day to every remaining part, deletes removed ones), `removeMeal`, `againMeal` (all parts back on the plate, name into an empty draft; all or nothing). Listens for `visibilitychange` and checks every minute so "today" follows the rollover. After the first render, `announceUpdate()` compares `version` with `banana:seenVersion:v1` and opens the What's new note (see SPEC "What's new"); `actions.showWhatsNew()` reopens it from Settings. `version`/`changelog` default to `src/version.js` (`VERSION` from package.json, `CHANGELOG` = `CHANGELOG.md?raw`).
  - `today.js`, `lookup.js`, `history.js`, `settings.js`: view renderers taking `{ state, today, day, draft, setDraft, pop, plateView, actions }` and returning nodes. Today lists `dayRows`: entry rows and meal rows (`button.entry.meal` with `.label` and `.parts`), both swipeable. `today.js` also exports `emptyState(text)` (the swaying smiling banana, shared with History) and `statusText`. `lookup.js` never logs or changes entries; its portions add a named part to the plate. `banana.js`: the inline SVG sprite (`SPRITE`, symbols `banana`, `banana-half`, `banana-face`), `ensureSprite()` (called by `mountApp`, once per document), `banana(fill, { over, pending, pop, i })` → `span.b.f0|f1|f2` (`.pending`: on the plate, drawn lighter with a wobble) with `<use>`s (`use.ghost` is the empty outline), `bigBanana()`, and `SILHOUETTE` (outline path for the tab icon and page pattern). Icons whose fill grew since `pop.from` get `.pop` and a `--i` stagger index; history bars with no entries get `.zero` (no stem). `plate-view.js`: `createPlateView(initialPlate, { onSelect })` → `{ el, update(plate), destroy() }`; one on Today and one in each editor, each with its own shadow filter id (`piece-shadow-N`). The tilted plate (viewBox 320×196; plate plane projected with `K` 0.56) built with `createElementNS` (names only via `textContent`): ellipses, `path.wedge[data-part]` (`.active` when there are several), `line.divider`, `text.wedge-label`, and a `g.piece[data-part]` per shown piece (`MAX_SHOWN` 40, `+N` badge), drawn back to front. Bodies are matched across updates by piece key: new ones get `.drop` (until the next update) and fall from above; a click on anything with `data-part` calls `onSelect`. Physics runs on `requestAnimationFrame` only while something moves (gravity and bounce for falling bananas, which press down the ones they land on; damped springs for sliding, sizes and wedge angles; a banana whose support went away falls); without `requestAnimationFrame`/`matchMedia` (jsdom) or with reduced motion it settles at once. The loop itself is untested; `heap.js` is. `swipe.js`: `attachSwipe(row, { onTap, onDelete, onAgain })` (pointer events; axis decided after 8 px; `touch-action: pan-y` keeps vertical scrolling native; the row's `<li>` gets `commit-left|right` past the full-swipe point; one open row at a time, closed by any press outside it) and the pure `swipeOutcome(dx, width)`. Today's rows use it: entries left → `actions.remove`, right → `actions.addPart(halves, label)`, tap → editor; meals left → `removeMeal`, right → `againMeal`, tap → meal editor. `whats-new.js`: `showWhatsNew({ title, releases, earlier })` (dialog with a sticky ✕ close button and Got it; text only via `textContent`). `editor.js`: the edit dialog (owns its own draft values until Save), with its own `createPlateView` of the entry as one part, updated from the stepper's `onChange`. `meal-editor.js`: `openPartEditor` (name, amount down to 0, Remove) and `openMealEditor` (a plate view of the remaining rows, refreshed on every amount, name and ✕; `onSelect` marks the row `.active`; name, per-part name/compact stepper/✕, day, Delete meal; focus starts on the heading). Both destroy their plate view on `close`. `dom.js`: `h()`, `stepper()`, `openDialog`/`closeDialog` (falls back to the `open` attribute where `showModal` is missing, e.g. jsdom). `toast.js` (one at a time, optional action button), `install.js` (`detectEnv`, iOS install help), `files.js` (`saveFile`: Web Share with files, else download; resolves `false` when the share sheet is cancelled), `storage.js` (`createStorage(backend)`: JSON get/set/remove that never throw; localStorage or memory).
- `src/main.js`: entry point (fonts, CSS, `navigator.storage.persist()`, SW registration). Untested by design; keep logic out of it. The plugin runs with `registerType: 'prompt'` (checked by `tests/build/config.test.js`): a new version installs and waits; `onNeedRefresh` calls `actions.setUpdateReady(restart)`, Settings offers Restart now (`actions.applyUpdate` → `updateSW(true)`), otherwise it takes over on the next launch. Don't switch to `autoUpdate`: its page code reloads the app when a new version takes over.
- `src/styles.css`: tokens with light/dark themes. Sprite colours are custom properties (`--peel`, `--shade`, `--shine`, `--ridge`, `--neck`, `--stem`, `--stem-end`, `--flesh`, `--seeds`, `--spot`, transparent unless overripe) that inherit into the `<use>` trees; `.b use.ghost` sets them all to `--ghost`; `.b.over` swaps in `--ripe-*` and `--spot-ink`; `.mini .b` is one colour. `--pattern` is the tiled page background built from `SILHOUETTE` (one tile per theme, fill inlined; regenerate it if the silhouette changes). `.bar.over` fills use `--ripe-peel`/`--spot-ink`. The meal plate uses `--rim`, `--rim-edge`, `--rim-side`, `--well`, `--plate-shadow`, `--wedge-active`, `--wedge-line`, `--wedge-label(-active)` and `--piece-shadow` (the `feDropShadow` flood colour). `assets/icon.svg` is the app icon source (the sprite art with colours inlined).
- `scripts/splash.js`: iOS launch screens. `SPLASH_DEVICES` (every iPhone screen size, portrait, in CSS points + pixel ratio), `splashFile`, `splashLinks(base)` (the `apple-touch-startup-image` tags, light then dark, injected into `index.html` by a tiny plugin in `vite.config.js`) and `splashSvg` (the smiling banana from the sprite on the app background). `scripts/build-icons.mjs` renders them to `public/splash/` (palette PNGs). They're excluded from the precache (`globIgnores`): iOS reads them only when the app is added to the Home Screen. Add a row when Apple ships a new screen size.
- `src/data/foods.json`: generated, committed; never edit by hand (fix the build rules, aliases or pins instead).
- `tests/lib`, `tests/ui` (jsdom via `// @vitest-environment jsdom`; `tests/ui/helpers.js` mounts with memory storage, a controllable clock, a recording `saveFile` and a small `FOODS` fixture for `loadFoods`), `tests/build` (separate config `vitest.build.config.js`).
- `.github/workflows/deploy.yml`: test, build, build tests, deploy to GitHub Pages on push to `main`.

## Rules
- TDD: write or update the failing test first. Flag any untested change.
- User text goes through `textContent` (the `h()` children). `h(..., { html })` is for static markup only, never data.
- Never derive an entry's day from its timestamp after creation; `day` is stamped once (see SPEC "Entry").
- Never hard-delete entries: deletion is a `deleted: true` marker so merges can't resurrect it.
- The food list is a reference for estimating. Look up may add a part to the plate named with the food and portion ("Bagel (regular)"), which can be edited before logging; it never logs by itself, and nothing else from the database (codes, other portions) goes into entries.
- A meal is ordinary entries sharing `meal.id`; keep it that way (per-part entries are what make totals, History and merges work without special cases).
- Changing the backup format means bumping `VERSION` in `backup.js` and keeping `parseBackup` able to read version 1.
- Keep README, CHANGELOG, SPEC and this file accurate to the code.
- `CHANGELOG.md` is shown in the app. Every release bumps `version` in package.json and adds a `## x.y.z — date` section whose bullets are written for the person using Banana; developer notes go under `### Developer`. `tests/lib/changelog.test.js` fails if the package version has no user-facing notes.
